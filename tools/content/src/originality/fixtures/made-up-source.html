Pond Notes: lists, loops & helpers

A list keeps its entries in the order you added them, and every entry sits at a numbered slot. The numbering begins at zero, which surprises many newcomers, because people usually count their belongings starting from one.

When you ask a list how many entries it holds, the answer is always one larger than the number of its final slot. Forgetting this small gap is the classic reason a program reaches past the end and receives nothing useful back. 

const shelf = ["tea", "rice", "salt", "oats"];
let longest = shelf[0];
for (let slot = 1; slot < shelf.length; slot++) {
  if (shelf[slot].length > longest.length) {
    longest = shelf[slot];
  }
}
console.log(longest);

A counting loop repeats its body while a condition stays true. The counter is checked before each pass, so the moment the condition fails, the body is skipped and the program continues with whatever comes after the closing brace.

Keeping a running figure across passes is a common chore. Create the figure before the loop begins, adjust it inside the body on every pass, and only trust its value once the loop has completely finished. 

function tally(weights) {
  let grams = 0;
  for (const weight of weights) {
    grams = grams + weight;
  }
  return grams;
}
console.log(tally([120, 80, 45]));

A helper that announces a result on the screen has not handed that result to its caller. Only a value that is explicitly sent back can be stored, compared, or passed along to the next helper in the chain. The word return is what sends it. 

const ledger = { paid: 3, owed: 7 };
ledger.owed = ledger.owed - ledger.paid;
console.log(ledger.owed);
